# BuSync 배차 엔진 (dispatch-engine)

인천 버스회사 실배차 데이터(2020.01~2026.06) 역공학 스펙 기반의 배차 생성/검증 코어.
**LLM은 배차표 셀을 채우지 않는다** — 코어는 Google OR-Tools **CP-SAT** + 결정론적 로테이션 전개.

## 구조

```
busync_engine/
  models.py      도메인 모델 (사업부/노선/그룹/차량/기사/순번/시프트/휴무유형)
  config.py      감차·표시 모델 설정 (DayClass, ReductionMode, DisplayMode)
  importer/
    weekly.py    주간배차표 파서 — 날짜 앵커(ISO/datetime/"금 5/1 일") 기반 상대좌표 추출
    inference.py 규칙 자동 추론 — 로테이션 순열, 감차 모델, 프로필, 스왑률 (온보딩 위저드 코어)
    worksheets.py 배차총괄(기사×날짜 A/P 그리드)·일일배차(노선 3단×출발지 블록) 파서
  rotation.py    1단계: 차량-순번 패턴 전개 (결정론)
  solver.py      2단계: CP-SAT 기사 배정 (H1~H6 하드, S1~S5 소프트)
  policy.py      회사별 설정 카탈로그 (22항목 — 토글/슬라이더/선택/범위)
  recommend.py   온보딩 추천 엔진 (추천값+신뢰도+근거)
  generate.py    생성 오케스트레이터 (정책 반영 E2E)
  explain.py     설명가능성 — "왜 이 기사가 이 슬롯인가"
  repair.py      국소 수리 — 당일 결원 → 후보 추천 → 원탭 확정
  leave.py       휴무신청 워크플로·대타 카운터·연차 자동계산
  audit.py       제약 감사 — H1~H6 위반 0건 검증 (위반 시 배포 차단)
  fairness.py    공정성 리포트 — F1 슬롯분포 / F2 주말휴무 / F3 대타 편차
  renderer.py    주간배차표 xlsx 렌더러 (기존 게시 양식 재현)
  backtest.py    백테스트 — 과거 월 초기조건 → 생성 vs 실제 셀 단위 일치율
cli.py           백테스트 실행기
service.py       FastAPI 서비스 (정책·초안은 data/에 파일 영속화)
tests/           15개 — 불변식 + 실데이터 검증 (1단계 100%, 배차총괄 120명 정합)
```

## 실측으로 확정한 규칙 (2026 성민 지선·간선)

**로테이션 = 그룹별 고정 순열 π** (매일 적용, 감차일에도 중단 없음, 월 경계 리셋 금지):

| 그룹 | N | 규칙 |
|---|---|---|
| 지선 가좌/일신 | 5 | +2 |
| 지선 삼산 | 8 | 순열 1→4→7→3→6→2→5→8 (+3 위주 +4 보정) |
| 간선 동춘동/삼산동 | 10/11 | −1 |
| 간선 원창동(37번) | 10 | −3 |

**감차(휴차) 2모델** — "휴차도 순환":
- `FIXED_SLOTS`: 요일클래스별 고정 언더라잉 휴차 슬롯. 차량이 로테이션으로 그 슬롯을 통과하며 쉼.
  (지선 전체: 토=일=삼산{4,5}·가좌{3}·일신{3} / 간선 동춘 토{3,8}·일{2,3,8}, 삼산동 토{1,2,3}·일{1,2,3,4})
- `VEHICLE_POINTER`: 차량 리스트 위 연속 포인터가 감차일마다 휴차 대수만큼 이어서 소비 (간선 37번).

**표시 2모드**: 지선 `KEEP`(휴차도 순번 표시, 기사 자리에 휴/O휴) / 간선 `COMPACT`(운행차만 1..M 재부여, 휴차 ○).

**짝궁 A/P 전환의 진짜 규칙** (역공학 스펙의 "휴무 후 스왑 74%"를 정제):
- 짝이 **동시에** 쉰 뒤 복귀 → 스왑 **90~92%**
- **혼자** 쉰 뒤 복귀(짝은 계속 근무) → 유지 **70~75%** (짝의 시프트 유지 98.4%가 강제)
- 연속 근무일 시프트 유지 98.4%

## 백테스트 결과 (스펙 5.1 프로토콜)

1단계 (순번 패턴, 목표 95%+): **지선 2026-05/06, 간선 2026-05/06 전부 100%**
— 규칙은 전월 데이터에서 자동 추론, 특별 감차일(아시아드·선거일)은 시나리오 입력.

2단계 (기사 배정, 목표 80%+): 지선 2026-05 셀 단위 62% / **차량 단위 80%**, 2023-06 셀 65% / 차량 81%.
- 불일치의 절반가량은 짝 내부 A/P 반전 — 위 전환 규칙으로도 10~25%는 담당자 재량(비결정적)이라
  셀 단위 80%는 이 데이터에선 도달 불가가 실측 결론. 차량 단위(누가 어느 차)는 목표 수준.
- 불일치 목록은 "예외 케이스"로 출력되어 담당자 검토 자료가 됨 (스펙 의도).
- 제약 감사: 모든 실행에서 H1~H6 위반 0건.

## 실행

```bash
python cli.py backtest \
  --workbook "~/Downloads/2026년 지선배차.xlsx" --division 지선 \
  --prev "지선배차표(2026년 4월)" --target "지선배차표(2026년 5월)" \
  --history "지선배차표(2026년 3월)" \
  --holidays 2026-05-01,2026-05-05,2026-05-25
```

환경 준비 (venv 생성 + 의존성 + 테스트):

```bash
./setup.sh
```

Node 백엔드 연동: `packages/backend/src/routes/engine.ts`가 `/api/engine/*`을
이 서비스로 프록시한다 (env `ENGINE_URL=http://localhost:8100` 설정 시 활성,
미설정이면 503 — 백엔드는 엔진 없이도 정상 기동). 프록시가 인증된 companyId를
`x-company-id` 헤더로 주입해 회사별 정책·초안이 격리된다.

admin-web: **AI 엔진 설정 화면**(`/dashboard/engine`, `EngineSettingsPage.tsx`)이
`GET /engine/catalog`를 읽어 설정 UI를 자동 렌더링한다 — 엔진에 설정이 추가되면
프론트 수정 없이 화면에 나타난다. 엑셀 업로드 → 추천 카드(추천값·신뢰도·근거)
→ [전체 추천 수락] 원탭 온보딩 → `PUT /engine/policy` 저장.

## 회사별 설정 시스템 (policy + recommend)

배차 스타일은 회사마다 다르다 — 엔진이 픽스하는 것은 **기본값뿐**이고,
모든 규칙은 회사가 켜고/끄고/조절한다.

- `policy.py` — **설정 카탈로그** 22개 항목 × 7개 카테고리(근무 규칙 / 차량·짝궁 /
  순번 로테이션 / 감차 / 휴무·선호 / 예비 운영 / 공정성). 각 항목은
  토글·숫자·슬라이더·선택형으로 선언되고 라벨·도움말이 붙어 있어 프론트가
  `GET /catalog` 하나로 설정 화면을 자동 렌더링한다. 기본값은 78개월 실측 기반.
- `recommend.py` — **온보딩 추천 엔진**. 업로드한 과거 배차표를 분석해 설정마다
  `추천값 + 신뢰도 + 근거 문장`을 만든다. 예:
  > `[pair_swap_rule] → joint_solo (0.90)` — "짝 동시휴 복귀 후 교대율 91%(513건),
  > 단독휴 복귀 후 교대율 27%(71건). 실측과 일치."
  담당자는 [추천 수락] 원탭으로 확정하거나 개별 수정한다. 확정은 항상 사람.

## 생성 모드 (generate.py)

`generate_month(과거 로스터, 정책, 연, 월, 승인휴무, 월초 구성)` →
패턴 전개 → CP-SAT 배정 → 감사 → 공정성 리포트.

- 수급 부족 슬롯은 실패가 아니라 **결행 후보**로 리포트 (H1 슬랙 + 큰 페널티).
- 가용일이 만근 하한보다 적은 기사(연차·입퇴사)는 자동 일할.
- 지선 2026-05 데모: 미충원 0 · 감사 위반 0 · 공정성 σ가 실제 수기 배차와 동급
  (대타 σ 6.20 vs 실제 6.93).
- `renderer.py`가 기존 게시 양식 그대로 xlsx 생성 — 자체 임포터 재파싱
  라운드트립 558/558 일치.

## 운영 모듈 (설명·수리·휴무)

- `explain.py` — **설명가능성** (스펙 0). 모든 셀에 대해 "왜 이 기사가 이 슬롯인가"를
  한국어 근거 문장 + 차선 후보(반사실)로 답한다. 기사 앱 '내 배차 설명' 화면용
  월간 서술(`explain_driver_month`)도 제공. "왜 나만 늦은 배차냐" 민원의 1차 방어선.
- `repair.py` — **국소 수리** (스펙 4-3). 당일 결원 시 전체 재생성 금지 — 해당 슬롯만
  놓고 후보를 스코어링(최근 30일 대타 부담·숙련도·그룹·연속근무·호출 부담)해 상위
  3명 추천 → 담당자 원탭 확정 → 그 셀만 교체 + 변경분 마킹. 오버라이드 이력은
  다음 달 공정성 계산에 반영.
- `leave.py` — **휴무신청 워크플로 + 대타 카운터 + 연차** (스펙 2.7/2.8).
  정원 내 자동 승낙("웬만하면 승낙"), 초과분만 스코어 정렬(호혜성 w1 + 선착순 w2 +
  여유인력 w3 + 최근 승낙률 w4, 연차·병가는 법정 권리로 최우선) 후 담당자 확인.
  대타 카운터(요청/승낙/거절) 영구 집계. 근로기준법 연차 자동계산
  (1년 미만 월 1개, 1년 이상 15개+2년마다 1, 상한 25) + 월중 입퇴사 일할.

## HTTP 서비스 (service.py)

Node 백엔드 연동용 마이크로서비스 (OR-Tools가 Python 전용):

```bash
uvicorn service:app --port 8100
```

| 엔드포인트 | 용도 |
|---|---|
| `GET /catalog` | 설정 카탈로그 (설정 화면 자동 렌더링) |
| `POST /analyze` | 엑셀 업로드 → 규칙 감지 + 설정 추천 (온보딩 위저드) |
| `POST /backtest` | 과거 월 재현 검증 리포트 |
| `POST /generate` | 월 배차 초안 생성 → `draft_id` (+감사/공정성/xlsx) |
| `GET /draft/{id}/explain` | 셀 배정 근거 ("왜 이 기사가 이 슬롯인가") |
| `GET /draft/{id}/explain-driver` | 기사 월간 설명 (기사 앱) |
| `POST /draft/{id}/absence` | 당일 결원 신고 → 대체 후보 3명 추천 |
| `POST /draft/{id}/repair` | 대체 확정 (해당 셀만 교체 + 변경 마킹) |
| `POST /leave/triage` | 휴무신청 자동 승낙/검토 분류 |
| `GET /leave/annual` | 근로기준법 연차 자동계산 |

## Railway 배포

**스크립트 한 방** (`railway login` + 프로젝트 링크만 되어 있으면 됨):

```bash
railway login                      # 최초 1회 (브라우저 인증)
railway link                       # 백엔드가 있는 프로젝트 선택
BACKEND_SERVICE_NAME=<백엔드서비스명> ./packages/dispatch-engine/deploy-railway.sh
```

스크립트가 하는 일: 엔진 서비스 생성(GitHub 연결 → push 시 자동 재배포) →
`PORT`·`RAILWAY_DOCKERFILE_PATH` 설정 → `/data` 볼륨 생성 → 배포 →
백엔드에 `ENGINE_URL` 주입.

빌드 컨텍스트는 **리포 루트**이고 `RAILWAY_DOCKERFILE_PATH`로 Dockerfile
위치를 지정하므로, 대시보드에서 Root Directory를 손댈 필요가 없다.

로컬 도커 빌드(리포 루트에서):

```bash
docker build -f packages/dispatch-engine/Dockerfile -t busync-engine .
```

주의: 엔진은 인증이 없다 — 반드시 백엔드 프록시 뒤(private network)에만 두고
공개 도메인(Generate Domain)을 만들지 말 것. 스크립트도 도메인을 만들지 않는다.
